# Test Patterns by Migration Theme — Java Modernization

A collection of test patterns for behaviors that tend to break in this domain, which should be
**systematically** incorporated into the baseline (Characterization Test) and the verify integration gate.
(For the common framework, see the harness's baseline-behavior.md template)

| Theme | Test Pattern | Reference |
|--------|--------------|------|
| Silent failure of security defaults | **Non-empty assertion**: verify that the page title and dynamic content are not empty strings (an OGNL allowlist, for example, returns empty rather than raising an exception). Run with diagnostic logging enabled (e.g. `struts.ognl.logMissingProperties=true`) | DP-2 |
| Form parameter binding | Confirm the **submit-to-result round trip** for representative forms (a binding failure manifests as an NPE or no response) | DP-2 |
| CSRF | **Submission tests for every POST path**: login, authenticated forms, anonymous POSTs (e.g. comments), multipart uploads. GET-only display checks cannot detect this | DP-3 |
| File upload | Confirm the **existence of the result** after the upload executes (saved file / DB record). Legacy APIs can do nothing with no exception | DP-2 |
| Generated HTML element IDs | Audit ID changes for elements generated by framework tags (submit/link, etc.). Base E2E selectors on CSS classes/attributes | DP-4 |
| UI layout / modals | When migrating CSS frameworks: whether buttons are positioned within the viewport (scrollIntoView), and whether modals display correctly (stacking context, changes to the JS API) | DP-4 |
| Locale / i18n | Note that server-side resolution uses the JVM default locale. Fix this in tests with `MAVEN_OPTS="-Duser.language=en -Duser.country=US"` | DP-4 |
| Authentication / authorization flow | The full login → protected page → logout flow (a Spring Security major upgrade can change filter chain behavior) | DP-3 |
| Input sanitization | Round-trip real data through HTML sanitizers/validators (edge cases such as quote styles, localhost URLs, etc.) | — |
| Existing test suite | Mode C (reuse the existing tests): treat all existing unit tests passing plus all E2E tests passing as the pillar of migration completion. Count **migrating the test infrastructure itself** (container plugins, WebDriver, headless configuration) as a Step | CP-5 |

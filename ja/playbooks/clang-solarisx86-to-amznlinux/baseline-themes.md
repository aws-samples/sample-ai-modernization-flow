# 移行テーマ別テストパターン — C / Solaris x86 → Amazon Linux

baseline（Characterization Test）と verify の integration ゲートに**系統的に**組み込むべき、
本ドメインで壊れやすい振る舞いのテストパターン集。
（共通の枠組みは harness の baseline-behavior.md テンプレートを参照）

| テーマ | テストパターン | 参照 |
|--------|--------------|------|
| Y2038 / time_t 64bit化 | **境界年スキャン**: 2036〜2040 + 2050 など境界前後の全年で日付の表示・保存・取得・往復を確認する。1項目でなく範囲でスキャンする（境界の前後で初めてズレが見える） | DP-5, DP-6 |
| ILP32→LP64 | **構造体レイアウト比較**: ワイヤー/永続化に使う構造体の sizeof/offsetof を新旧で比較。ポインタ往復（格納→取得）の値一致 | DP-3, DP-7 |
| RPC/ワイヤープロトコル | 旧クライアント相当の**32bitシリアライズ往復テスト**。エンコード結果のバイト列固定 | ADR実例: xdr_time_t_compat |
| ロケール・TZ | 代表ロケール/タイムゾーンでの出力固定（glibc と旧OSで TZ 文字列解釈が異なる。`TZ=UTC0UTC` は glibc で米国東部の DST 規則が適用され、遷移表の範囲外では EST/EDT のオフセットになる） | DP-4 |
| 共有ライブラリ | soname リンクの解決（ldd で "not found" ゼロ）、シンボルの重複ロード有無 | （過去の移行プロジェクトで繰り返し得られた教訓） |
| デーモン起動系 | 起動シーケンスの観測点固定: プロセス生存（timeout rc=124=生存）、RPC登録（rpcinfo）、X property等の外部から見える状態。**前提デーモン（rpcbind等）と環境変数（LD_LIBRARY_PATH）をテスト前提条件に明記** | CP-4 |

# 互換スイッチの一覧と読み方（.NET Framework → モダン .NET）

一次情報の URL は [runtime-generation-differences.md](runtime-generation-differences.md) §7 に集約している。

## この文書の使い方 — スイッチは変更の索引である

> **互換のためのスイッチが用意されていることは、その振る舞いが変わった証拠である。**

changelog を読む前に**互換スイッチの一覧を引く**と、破壊的変更を短時間で洗い出せる。
「何が変わったか」を網羅的に探すより、「何を戻せるようにしたか」を見るほうが速い。
スイッチ名は変更の**索引**として機能する。

**逆向きにも効く。** スイッチが**存在しない**差異は、**戻す手段が無い**ということである。
そこは互換性で吸収できないので、コードを直すか成功基準を変えるしかない
（→ ADR 相当の判断になりやすい）。

## スイッチ一覧

| スイッチ | 対象 | 何が変わった証拠か | 移行での扱いの目安 |
|---------|------|-----------------|-----------------|
| `InvariantGlobalization`<br>（`System.Globalization.Invariant` / `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT`） | ランタイム | カルチャ依存データを使う実装が既定になっていること。既定は `false` | ⚠️ **安易に有効化しない。** 有効にすると `Compare` / `IndexOf` / `LastIndexOf` が**比較オプションの指定に関わらず常に序数**になり、ソートキーも序数相当になる。ICU でも NLS でもない**第三の挙動**である。タイムゾーンの ID 相互解決も壊れる（ICU 前提のため） |
| `System.Globalization.UseNls`<br>（`DOTNET_SYSTEM_GLOBALIZATION_USENLS`） | ランタイム | **ICU が既定になった**こと（.NET 5 で導入） | **Linux では無意味**（Windows 限定）。Windows 上の版上げ案件でソート順を現行維持したい場合の逃げ道。.NET 9 以降は環境変数が最優先される |
| `DOTNET_ICU_VERSION_OVERRIDE` | ランタイム | ICU の**版差で挙動が変わりうる**こと。Linux では既定でシステムの ICU をロードし、指定版が無ければ最新にフォールバックする | 常用しない。**版差の再現性が必要になったとき**の手段として記録しておく。⚠️ **.NET 10 で環境変数名が変わった**（旧 `CLR_ICU_VERSION_OVERRIDE`）ため、古い手順書をそのまま使うと効かない |
| `UseLazyLoadingProxies()` | EF Core | **遅延読み込みが既定 OFF になった**こと（EF6 は既定 ON） | プロキシパッケージの追加 + `virtual` ナビゲーションが前提。**「有効化して現行に寄せる」か「明示 `Include` に書き換える」かは ADR 相当の判断**である |
| `ConfigureWarnings` | EF Core | 例外ではなく**警告で済まされる差異がある**こと | **開発環境で警告を例外に昇格させる**のが有効（遅延読み込みの `Include` 漏れ・`OrderBy` なしの行制限操作を実行時に落とせる）。本番で有効にするかは別判断 |
| `AsSplitQuery()` / `QuerySplittingBehavior` | EF Core | `Include` の展開が**単一クエリに統合された**こと（EF Core 3.0） | 既定（単一クエリ）でデカルト積による取得行数の爆発が出たときの戻し手段。**無症状で本番負荷にだけ出る**ので、性能特性を測ってから決める |
| `UseRelationalNulls(true)` | EF Core | EF Core が **null 比較に補正項を自動追加している**こと | ⚠️ **有効化すると SQL の3値論理そのままになり結果が変わる。** 既定（`false`）から動かさない |
| リクエストローカライゼーションミドルウェア | ASP.NET Core | **リクエストごとのカルチャ決定が既定では行われない**こと | **既定カルチャを明示固定するために使う。** 未設定だとプロセスの既定カルチャ（環境依存）に落ちる。「コンテナの既定に任せる」は環境変更でサイレント障害になる |
| `MvcOptions.SuppressAsyncSuffixInActionNames` | ASP.NET Core MVC | アクション名から `Async` 接尾辞が**自動除去されるようになった**こと（既定 `true`） | `false` にすれば現行 URL を維持できるが、**フレームワークの規約から外れる**。文字列直書き URL を `Url.Action` に直すほうが筋が良い（→ 観点 MP-6） |
| ネイティブライブラリのコピー制御 MSBuild プロパティ | ネイティブ依存パッケージ | **ネイティブ資産が出力先にコピーされない既知問題がある**こと | 回避プロパティに頼る前に、**ビルド成果物にネイティブ資産が実在することを検証ゲートの期待リストに入れる**（CP-7）。「動いた」ではなく「存在する」を機械で押さえる |
| CA1307 / CA1309 / CA1310 | アナライザ | カルチャ依存比較 API の**実装が変わった**こと | ⚠️ **.NET 10 時点でも既定で無効。** opt-in が必要である（`AnalysisMode=All` + `WarningsAsErrors`）。**有効化しなければ「警告ゼロ」は「問題なし」を意味しない** |

## スイッチを扱うときの規律

1. **「互換スイッチで戻す」を既定の解にしない。** スイッチは移行を通すための一時的な足場であり、
   残すなら**なぜ残すかを ADR に書く**。書かないと次の保守者が「なぜ既定から外れているのか」を問う
2. **スイッチを入れたら、それが何を変えたかを検証ゲートで固定する。**
   例: 不変モードを有効にしたなら、ソート順に依存する画面のアサーションを追加する
3. **スイッチの名前と既定値は世代で変わる**（実例: ICU 版指定の環境変数名が .NET 10 で改名）。
   **古い手順書をコピーしない。** 採用する版のドキュメントで名前と既定値を確認する
4. **アナライザ系のスイッチは「無効なら警告が出ない」ことを忘れない。**
   検出器を有効化していない状態の「0件」は**検出できていない**のと区別できない（CP-13）

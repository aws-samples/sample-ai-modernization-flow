# 移行テーマ別テストパターン — Java モダナイゼーション

baseline（Characterization Test）と verify の integration ゲートに**系統的に**組み込むべき、
本ドメインで壊れやすい振る舞いのテストパターン集。
（共通の枠組みは harness の baseline-behavior.md テンプレートを参照）

| テーマ | テストパターン | 参照 |
|--------|--------------|------|
| セキュリティデフォルトのサイレント障害 | **非空アサーション**: ページタイトル・動的コンテンツが空文字でないことを検証（OGNLアローリスト等は例外を出さず空を返す）。診断ログ（例: `struts.ognl.logMissingProperties=true`）を有効にして実行 | DP-2 |
| フォームパラメータバインド | 代表フォームの**送信→結果反映の往復**を確認（バインド不発はNPEまたは無反応として発現） | DP-2 |
| CSRF | **全POST経路の送信テスト**: ログイン、認証後フォーム、匿名POST（コメント等）、multipartアップロード。GET表示だけでは検出不能 | DP-3 |
| ファイルアップロード | アップロード実行後の**結果の存在確認**（保存ファイル/DBレコード）。旧APIは例外を出さずに不発になる | DP-2 |
| 生成HTML要素ID | フレームワークタグ生成要素（submit/link等）のID変化を監査。E2EセレクタはCSSクラス/属性ベースに | DP-4 |
| UIレイアウト/モーダル | CSSフレームワーク移行時: ボタンのビューポート内配置（scrollIntoView）、モーダルの表示（stacking context、JS APIの変化） | DP-4 |
| ロケール/i18n | サーバー側はJVMデフォルトロケールで解決されることに注意。テストは `MAVEN_OPTS="-Duser.language=en -Duser.country=US"` で固定 | DP-4 |
| 認証・認可フロー | ログイン→保護ページ→ログアウトの一連フロー（Spring Securityメジャー更新でフィルタチェーン挙動が変わる） | DP-3 |
| 入力サニタイズ | HTMLサニタイザ・バリデータの実データ往復（クォート形式、localhost URL等の境界ケース） | — |
| 既存テストスイート | モードC（既存テストを流用）: 既存ユニットテスト全PASS + E2E全PASS を移行完了の柱にする。**テスト基盤自体の移行**（コンテナプラグイン、WebDriver、ヘッドレス設定）をStepとして計上 | CP-5 |
